# 实测依据与适用范围

公开证据摘要在 [source/evidence.json](../source/evidence.json)。只保留与分流结论有关的数据，不公开账户、设备标识、节点凭据、网络地址或原始连接日志。

## 约三个月 Shadowrocket 使用经历

截至 2026-09-06，维护者本人反馈：使用 Shadowrocket 约三个月，先后使用香港、新加坡、日本、台湾、德国、美国节点；期间账号正常，没有遇到异常登录、验证码困扰、属地回落或功能异常。

这是维护者自述的真实使用经历，不是逐日统计，不意味着每个地区都连续使用三个月，也不意味着最终导出的同一版本规则从第一天起完全没变。不能据此保证任何账号在任何节点下都不会遇到风控。

## PassWall2 / Xray 手机实测

2026-09-06，在保留既有 API 后缀代理和媒体例外的前提下采样，用户反馈：“没什么卡顿的感觉，IP 也都是香港”。

| 已识别类别 | 记录 |
| --- | ---: |
| API 代理 | 135 次连接，25 个主机 |
| 媒体直连 | 270 次连接，98 个主机 |
| `zjcdn.com` 视频主机直连 | 58 次 |
| `pull-flv-*` 直播主机直连 | 24 次 |
| 音乐关键词例外直连 | 5 次 |

API 与媒体各自观察到对应的隧道/直连建立事件；最终体验判断来自用户实际操作。连接数不是 HTTP 请求数、字节量或代理流量比例。

手机后台流量和无法嗅探域名的连接没有直接归类为抖音。此次记录没有独立账号查看新发布内容的验收，因此不补写成“公开发布全场景验证”。没有解密请求或响应内容。

## 仍然保留代理的候选

`api-play-zjg.amemv.com`、`tos-d-x-hl.snssdk.com`、部分模板或上传相关主机曾出现代理命中。现有证据不能证明它们与属地无关，也没有量化浏览瓶颈，所以没有为了减少代理条数而添加直连。

## 适配不等于真机实测

Shadowrocket 的经历与 PassWall2 的日志不能直接迁移成 Surge、Loon、QX、Stash、Mihomo、v2rayNG、v2rayN、sing-box 客户端全部实测通过。其他格式从同一规则源生成，执行可复现的结构、顺序和合并检查；核心格式检查与手机端验收分开记录，见[兼容性](compatibility.md)。
