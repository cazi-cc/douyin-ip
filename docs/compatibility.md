# 兼容性与验证层级

“规则生成”“核心检查”“客户端导入”“真实账号使用”是不同层级。本表不把通用规则测试冒充所有软件的手机验收。

| 适配 | 交付形态 | 现有依据 | 仍需终端验证 |
| --- | --- | --- | --- |
| Shadowrocket | 模块 + 手动规则 | 维护者约三个月策略使用反馈、规则顺序检查 | 新导出模块在具体版本的导入与效果 |
| PassWall2 / Xray | 两组分流域名清单 | 手机日志、用户播放与香港属地反馈 | 其他固件/ACL/网络的最终路径 |
| Loon | 插件 | 官方插件格式/PROXY 绑定说明、规则语义检查 | 插件导入、策略指定与实际使用 |
| Surge | 直连模块 + API 规则 | 官方模块限制、分离规则检查 | iOS/macOS 具体版本的最终顺序 |
| Quantumult X | 分离规则资源 + 本地片段 | 官方配置样例、转换语义检查 | 资源/本地优先级、DNS 与 App 行为 |
| Stash | `.stoverride` | YAML 检查、官方前插数组语义 | 实际多覆写合并与播放 |
| Mihomo 客户端 | 规则集 + 脚本/合并工具 | 核心检查入口、合并保留与顺序测试 | CMFA/FlClash/Verge 界面与手机效果 |
| v2rayNG / v2rayN | 路由规则数组 | 上游实体与导入实现、合并检查 | 已安装版本的 UI 行为与核心转换 |
| sing-box | 原生规则集 + 路由片段 | 原生检查入口、前处理顺序测试 | 各图形客户端的导入和实际接管 |

本次实际执行的检查及核心版本见[验证记录](validation.md)。

## 版本范围

- Mihomo 适配依赖 `type: inline` 规则集与 `behavior: classical`。较旧 Clash 核心不保证支持；独立 `.yaml` 规则集可用于已有 provider 配置。
- sing-box 路由片段使用 1.11 起的 `action: route` 和内联规则集。source 文件用兼容的 schema 1 域名字段；原生合并工具针对 1.11+，核心检查以记录中的版本为准。
- v2rayN 教程针对 Xray 核心路径。它可选择其他核心，但不自动获得相同的验证结论。
- 模块/插件的局部覆盖能力不意味着能够覆盖 TUN 排除、加密 DNS、未知 IP 或主配置里的所有前置行为。

## 发布前的手机验证建议

每个有设备的客户端至少核查：导入没有重置节点与原路由、媒体先于 API、代理目标正确、DNS/IPv6 路径符合预期、视频图文直播正常、公开属地符合所选出口、停用后能恢复原配置。没有测试的项目继续标注未验收。
