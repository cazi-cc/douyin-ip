# 常见问题

## 能保证账号绝对安全吗？

不能。维护者三个月使用期间没有遇到账号异常，这是个人经历；不是对平台规则、节点信誉和所有账号的保证。规则本身不收集密码、Cookie，不安装解密证书，也不修改 App。

## 为什么还是国内属地？

先确认规则模式、目标节点的实际出口地区、媒体/API/通用规则顺序，再确认手机流量确实经过该客户端。使用软路由时额外检查内核提前直连和 IPv6 接管。

重连客户端、退出抖音后台再打开，让新连接使用新规则。平台更新可能有延迟；主页和评论也可能沿用历史显示。不要用某个 IP 查询网站的结果代替抖音验收。

## 为什么装了以后更慢？

检查是否误用全局代理、把 API 规则放在媒体前、覆盖原 DNS，或选择了质量较差的节点。先撤销本项目确认差异；不要直接把整个 `amemv.com` 改成直连来掩盖问题。

## 为什么两条 API 大域要保留？

同一个域名可能承载多个功能，HTTPS 请求路径又没有解密。现在没有足够证据把它们压缩成一个“专用查 IP 接口”。宁可保留已验证的兜底，再逐项研究有依据的媒体例外。

## 需要固定一个地区吗？

建议验证时固定一个稳定节点。自动切换不同地区、回退直连或多跳出口会增加结果的不确定性。项目不提供自动选节点、自动刷新属地或多账号功能。

## 会减少多少代理流量？

当前没有完整字节统计，不能提供百分比承诺。媒体直连有实测连接证据，但连接数并不反映视频大小。

## 能不能直接导入任意一个文件？

不能。模块、规则集、路由数组和完整订阅是不同东西。尤其 v2rayNG 直接导入两项规则可能重置原列表；Surge 的媒体模块也不能单独完成 API 代理。请使用对应教程。

## 如何撤销

- Shadowrocket / Loon：停用项目模块或插件。
- Stash：停用项目覆写。
- Surge：停用媒体模块，同时删除 API 规则/引用。
- QX：停用两份远程资源，或删除项目本地规则。
- Mihomo 客户端：停用项目扩展，或切回原配置副本。
- v2rayNG / v2rayN：删除项目两项路由，或恢复导出的原路由方案。
- sing-box / Xray：切回合并前副本；手动用户删除项目规则及规则集。
- PassWall2：只撤销本次新规则和对应选项，不用历史全量备份覆盖其他网络改动。

然后重连客户端、重开抖音。

## 反馈问题要提供什么？

客户端和版本、内核版本、节点地区、接入方式、具体异常、少量必要的域名和命中策略，以及是否 IPv6。删去账号、完整 IP/MAC、订阅、UUID、节点服务器、Token、Cookie、带鉴权参数的 URL 和私人策略名。

不要把完整配置、全屋日志或订阅链接贴到公开 Issue。本地 `local/` 文件夹用于个人合并输入输出，已默认忽略。
