# PassWall2

面向已正常运行 PassWall2 的 OpenWrt / iStoreOS 用户。本项目提供规则清单与界面设置，不提供会覆盖你全家网络的整包配置或一键 UCI 脚本。

## 加两组规则

先备份当前 PassWall2 配置，并确认手机实际使用哪个 ACL、分流节点与核心。不要只看全局开关，独立 LAN ACL 可能采用另外的核心。

在分流规则管理中新建：

| 顺序 | 建议名称 | 域名列表 | 出站 |
| --- | --- | --- | --- |
| 1 | Douyin-IP-Media | [media.domains](../../configs/passwall2/media.domains) 的全部内容 | 直连 |
| 2 | Douyin-IP-API | [api.domains](../../configs/passwall2/api.domains) 的全部内容 | 你的固定目标地区节点 |

两组都允许 TCP/UDP，不限制单个端口。将它们分配到**手机实际使用的分流节点**，并排在通用国内 GeoIP/域名规则前；不要照抄维护者的节点 ID 或 ACL 名称。

## 域名规则必须有机会被执行

在这个分流节点上检查“启用 GeoIP 数据解析”和“直连 DNS 结果写入 IPSet”等内核快捷选项。如果它们让国内 IP 在进入核心前被直连，会覆盖本项目的 API 代理意图。维护者实测中，关闭这两项才恢复了正确结果。

这是**对相应分流节点的必要设置检查**，不建议不分范围地改全局。进入本地核心不等于出国：媒体仍可由 `direct` 在国内访问。

保证相关入站能嗅探 HTTP/TLS/QUIC；API 使用对应代理的 DNS，媒体使用适合本地宽带的解析。存在 IPv6 时要核查 IPv6 TCP/UDP 同样被接管，不能只验证 IPv4。本项目不改 IPv6、防火墙、DHCP、Mesh 或其他服务。

## 验证

保存前核对顺序，按需重载 PassWall2，等待 DNS 与原有旁路/远程管理服务恢复，再重开手机 App。

可短时查看来源为手机的连接：API 两后缀应命中代理；`awememusicpgc` 等媒体例外应先直连。随后由手机检查播放、评论、直播和公开属地。网页出口检测不能代替这一步。

没有复现问题时不要打开长期详细日志。检查结束后恢复原日志级别。

## 撤销

只删除本项目两组规则及其节点映射，或恢复本轮开始前备份中的对应选项。不要恢复数日前的全套防火墙备份覆盖后来配置。是否重新启用内核快捷选项应单独判断：重新打开可能再次绕过域名优先级。

本项目的最新一次手机采样来自 PassWall2 / Xray，详见[实测依据](../evidence.md)。不同固件、核心和选项名称仍需以你的运行配置为准。
